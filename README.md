# dsh-prompt-boost

> 给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）的输入框加一颗 **✨**：
> 一句话草稿 → 一份信息完备、可直接执行的提示词。改完还能一键撤回。

**零配置**：不用填 API Key，不用填接口地址，直接复用你在 DSH「设置 → 模型」里已经配好的提供商与凭证。

```
输入：帮我做个报表
  ✨
输出：请帮我制作一份数据报表，需明确：① 报表主题与使用场景；② 数据来源与字段；
      ③ 需要展示的核心指标与维度；④ 期望的呈现形式（表格/图表/看板）；
      ⑤ 是否需要按时间或分类对比。若信息不全，请先列出你需要的字段再开始。
```

## 核心功能

| 功能 | 说明 |
| --- | --- |
| **✨ 一键增强** | 点一下，当前草稿被改写成更清晰、可执行的提示词，**原地替换**输入框内容 |
| **↩ 撤回** | 优化后 30 秒内可一键还原原文；你手动改过草稿则自动失效，不会冲掉你的编辑 |
| **6 种模板** | 通用结构化 / 编程与技术专家 / 文案与内容创作 / 严谨推理与研究 / 极简精练 / 自定义 |
| **模板可编辑** | 插件详情页下拉框选模板 → 查看完整提示词 → 改 → **另存为自定义模板** |
| **空输入自动隐藏** | 输入框为空时按钮不出现，不占地方 |

---

## 主要特性

- **免 Key** —— 走 DSH 自己的 LLM 层（`ctx.llm.stream`），凭证、代理、重试、限流全由宿主负责
- **不污染会话** —— 增强是一次**独立的旁路调用**，不改动你当前会话的主模型，也不往上下文里塞东西
- **语言一致** —— 中文进中文出，英文进英文出，中英混写保持混写，不翻译
- **不越权改写** —— 只改"怎么说"，不改"要什么"：不替你选技术栈、不补你没提的需求、不回答你的问题
- **内置模板不可覆盖** —— 编辑任何模板后保存都落到「自定义」，升级插件不会冲掉你的改动
- **零运行时依赖** —— 纯 ESM + 原生 `fetch`，没有 `node_modules`

## 快速开始

### 环境要求

- DeepSeek Harness **≥ 0.1.7-rc.2**（已在 **0.2.0-rc.2** 上实测）
- 已在 DSH 里配好至少一个模型提供商（设置 → 模型）

### 安装

**方式一：桌面端（推荐）**

插件管理 → 从本地目录添加 → 选中本项目目录 → 启用 → 重载插件。

**方式二：CLI**

```bash
dsh plugin --profile <profile名> add /path/to/dsh-prompt-boost
dsh --profile <profile名> --dump-config    # 确认多了一层 # == dsh-prompt-boost
```

**方式三：从 Git 安装**

```bash
dsh plugin --profile <profile名> add github:w2018/dsh-prompt-boost
```

> ⚠️ **不要直接 `pnpm add`**。它只把包装成普通依赖，不会写进 `dsh.profile.bundles`，
> 而 bundle 层是靠这个列表激活的 —— 少了这一步插件等于没装。
> 如果已经 `pnpm add` 过，把包名手工追加到 `dsh.profile.bundles` 末尾即可。

### 配置

**不需要任何配置。** 装完重启 DSH 就能用。

模型与凭证自动按这个顺序解析：

1. `cordis.patch.yml` 里显式指定的 `provider` / `model`
2. DSH 系统设置里的默认模型
3. 第一个能列出模型的提供商的第一个模型

### 第一次使用

1. 在输入框写一句需求（比如「帮我做个报表」）
2. 输入框右下、**模型选择器左侧**出现 `✨ 增强`
3. 点它 → 草稿被替换成改写版，按钮变成 `↩ 撤回`
4. 满意就直接回车发送；不满意点「撤回」还原

## 使用示例

### 1. 基础：把含糊需求写清楚

```
你写：这个代码有 bug 帮我看看
结果：请分析以下代码中的缺陷：说明触发条件与根因、影响范围、最小修复方案，
      以及验证修复是否生效的步骤。若信息不足，请先列出你需要我提供的文件或报错信息。
```

### 2. 换风格：同一句话，不同模板

| 模板 | 「写个爬虫」的改写方向 |
| --- | --- |
| 🌟 通用结构化 | 补齐目标、范围、输出格式 |
| 💻 编程与技术专家 | 追加架构层次、异常与边界、规范与验证方式 |
| ✍️ 文案与内容创作 | 明确受众、渠道、语气、行动号召 |
| 🔬 严谨推理与研究 | 要求推理链、反例、适用边界 |
| ⚡ 极简精练 | 压到最短且不丢关键约束 |

切换方式：插件管理 → 增强提示词 → 配置 → 下拉框选择。**点选即生效**，下一次点 ✨ 就用它。

### 3. 自定义模板

1. 插件详情页 → 下拉框选任意模板 → 编辑器载入它的完整内容
2. 直接改（比如加一条「一律补上验收标准」）
3. 点「**保存为自定义模板**」
4. 下拉框自动切到你的自定义模板，之后点 ✨ 都用它

> 内置模板本身不可覆盖 —— 编辑后保存一律落到「自定义」，这样升级插件不会冲掉你的改动。

### 4. 查看完整提示词

编辑器里看到的是**模板自身**的内容。点「查看完整系统提示词」会展开**真正发给模型的完整 system prompt**
（内置基础提示词 + 你的模板，实时包含未保存的改动）。

## 模板体系

| id | 图标 | 名称 | 侧重 |
| --- | --- | --- | --- |
| `general` | 🌟 | 通用结构化 | 清晰目标 / 格式约束（默认） |
| `code` | 💻 | 编程与技术专家 | 架构设计 / 边界异常 / 规范 |
| `copy` | ✍️ | 文案与内容创作 | 去 AI 腔调 / 生动语感 / 吸引力 |
| `research` | 🔬 | 严谨推理与研究 | 深度思维链 / 辩证反例 / 自洽 |
| `minimal` | ⚡ | 极简精练 | 剔除废话 / 直奔核心 / 高信噪比 |
| `custom` | 🛠 | 自定义提示词 | 自由编辑专属优化逻辑 |

前 5 个 = 内置基础提示词 + 一段风格指令；`custom` 用你自己写的整段指令。

配置文件位置：`$DSH_HOME/storages/prompt-boost.json`（默认 `~/.dsh/storages/prompt-boost.json`）

```json
{
  "preset": "custom",
  "customPrompt": "一律补上验收标准；必须给出一个反例。",
  "customLabel": "我的规范"
}
```

## 配置项

一般不需要。想把增强固定到某个模型时，编辑 `~/.dsh/profiles/<profile>/cordis.patch.yml`：

```yaml
- id: dsh-prompt-boost
  name: "dsh-prompt-boost"
  config:
    provider: deepseek-official   # 提供商 id
    model: deepseek-flash         # 模型 id
    maxChars: 800                 # 增强结果的长度上限
    timeoutMs: 60000              # 单次调用超时
```

> ⚠️ patch 会**整体替换**目标行的 `config`，不是深合并 —— 要改哪个键，就把需要的键全写全。

## 工作原理

DSH 插件分**双端**，本项目也按这个分工：

```
┌─ Client（浏览器/WebView）──────────────┐      ┌─ Host（Node）─────────────────┐
│ 插槽 conversation.input.right          │      │ POST /api/prompt-boost/enhance│
│   ✨ 按钮（模型选择器左侧）            │ ───► │   ↓                           │
│   读草稿 useInput / 写回 setDraft      │      │ ctx.llm.stream(...)           │
│   撤回状态（30s / 编辑即失效）         │ ◄─── │   用 DSH 已配置的模型与凭证   │
│ 插槽 plugins.bundle.config             │      │ GET/POST /settings（模板）    │
│   模板下拉框 / 编辑 / 另存为           │      │ ~/.dsh/storages/*.json        │
└────────────────────────────────────────┘      └───────────────────────────────┘
```

- **API Key 只在 Host**，浏览器端拿不到也不该拿
- 增强是**独立调用**，不进入会话上下文，不影响你选的主模型
- 提示词与后处理对齐 WorkBuddy 内置「增强提示词」：语言一致优先、≤800 字、只输出改写结果

## 常见问题

**Q：按钮没出现？**
检查三件事：① 输入框里有文字（空输入会隐藏）；② 插件已在 `dsh.profile.bundles` 里；③ 重启过 DSH（profile 清单只在启动时读）。

**Q：点按钮报「DSH LLM 服务不可用」？**
说明 `ctx.llm` 没挂上。先确认 设置 → 模型 里至少配了一个提供商，并且能正常对话。

**Q：点按钮报「未在 DSH 中找到可用的模型路由」？**
同上 —— 没有任何 provider 能列出模型。去设置里补一个。

**Q：提示「自定义模板还是空的」？**
你把模板切到了 `custom` 但没填内容。去插件详情页填一段，或换回预设模板。

**Q：增强用的是哪个模型？**
把鼠标悬停在按钮上，tooltip 会显示 `用 DSH 已配置的 <provider>/<model> 改写当前输入`。

**Q：会不会改坏我选的主模型？**
不会。增强是一次旁路调用，不改会话配置、不写会话历史。

## 开发与测试

```bash
# Host 半端：不启动 DSH 跑全部路由（设置写到临时 DSH_HOME，不碰真实 ~/.dsh）

# 双端加载自检：在 profile 目录下用 DSH 自带 node 跑

  /path/to/dsh-prompt-boost/test/load.mjs

cd /path/to/dsh-prompt-boost
PB_TEST_DEPS=/tmp/pb-test/node_modules node test/panel.mjs
```
